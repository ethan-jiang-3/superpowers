# 04 — 演化与背景：历史、决策、教训

## 这个目录研究什么

前四个目录研究的是 Superpowers 的"**现在**"——它的使用方法、技术架构、设计哲学、可借鉴模式。

这个目录研究的是 Superpowers 的"**过去**"——它怎么演化成今天这样，经历了哪些关键决策，犯过什么错误，学到了什么教训。

具体问题：

1. **技能是怎么被创造出来的？** 不是抽象的方法论（那是 writing-skills 的内容），而是**一个具体技能的真实诞生过程**——systematic-debugging 从 idea 到第一个可用版本的完整日志
2. **94% PR 拒绝率的背后是什么？** 不是数据本身，而是这个标准是怎么形成的，维护者拒绝了什么、接受了什么、为什么
3. **版本是怎么演化的？** 从 RELEASE-NOTES 中提取关键转折点——哪些版本是增量改进，哪些是结构性变化

---

## 为什么需要这个维度

理解一个项目的过去，才能真正理解它的现在。

- **94% PR 拒绝率**——如果不看被拒绝的 PR 是什么样的，你无法理解 CLAUDE.md 里那些严厉的措辞为什么存在
- **CREATION-LOG**——如果不看一个技能的真实创建过程，writing-skills 的 RED-GREEN-REFACTOR 方法论就只是一个抽象概念
- **版本历史**——如果不看 RELEASE-NOTES，你不知道哪些设计决策是被反复验证的，哪些是后来加入的

这不是"历史兴趣"——这是理解 Superpowers 当前设计决策的必要上下文。

## 与其他目录的关系

```
_digest/
├── 00-学习路径/    ← 当前 Superpowers 的使用方法
├── 01-项目架构/    ← 当前的技术架构
├── 02-设计哲学/    ← 当前的设计思想
├── 03-可借鉴模式/  ← 当前可提取的模式
└── 04-演化与背景/  ← ★ 当前目录：这些"当前"是怎么演化来的
```

04 为前面所有目录提供了**时间维度**——让你不仅知道 Superpowers "现在是什么样的"，也知道它"是怎么变成这样的"。这种历史视角对于判断哪些设计是核心的（经历过多次迭代验证）、哪些是较新的（可能还在调整中）至关重要。
