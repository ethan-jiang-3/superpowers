# 03 — 纵深防御质量模型

## 这是什么

Superpowers 不在一个环节做质量检查——它用五层独立防线叠加。每一层有不同的执行者（不同 agent）、不同的检查标准、不同的盲区。越过多层比绕过单层难得多。

这个设计直接可以移植到任何需要 agent 产出质量的系统。

---

## 五层防线

```
Layer 1: TDD                  ← 同一 agent 自我检查
    ↓
Layer 2: Spec compliance      ← 独立 subagent
    ↓
Layer 3: Code quality         ← 独立 subagent
    ↓
Layer 4: Verification         ← 同一 agent 自我检查
    ↓
Layer 5: Final review         ← 独立 subagent（看到完整 diff）
```

---

## 逐层拆解

### Layer 1: TDD — 功能正确性

- **谁做**：实现者 agent 自己
- **检查什么**：功能逻辑、回归、边界条件
- **漏什么**：过度构建（实现了 spec 没要求的东西）、对 spec 的理解错误、代码质量
- **铁律**：NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST
- **绕过难度**：低——就跳过而已

### Layer 2: Spec Compliance — 规格合规

- **谁做**：全新的 spec reviewer subagent
- **检查什么**：实现的和 spec 要求的是否精确一致
- **关键设计**：reviewer prompt 写 "CRITICAL: Do Not Trust the Report"——实现者可能乐观报告自己的完成度，reviewer 必须独立验证
- **漏什么**：代码质量（有意留给 Layer 3）
- **绕过难度**：中——需要操控另一个 subagent

### Layer 3: Code Quality — 代码质量

- **谁做**：另一个全新的 subagent
- **检查什么**：安全（SQL 注入、凭证泄露）、架构、可维护性、命名、文件增长是否超出计划
- **输出**：Strengths、Issues (Critical/Important/Minor)、Assessment
- **漏什么**：跨 task 集成问题（每个 reviewer 只看到一个 task 的 diff）
- **绕过难度**：高——独立 reviewer + 自己的判断标准

**顺序不可颠倒**：spec review 必须先于 code review。在没有确认"做对了东西"之前去审查"代码写得好不好"是浪费——spec review 可能发现多余的代码直接被删。

### Layer 4: Verification — 证据门禁

- **谁做**：实现者自己（但强制在声称完成前）
- **检查什么**：所有声称是否有新鲜验证证据
- **铁律**：NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
- **5 步门函数**：IDENTIFY → RUN → READ → VERIFY → ONLY THEN claim
- **绕过难度**：中——需要主动跳过门函数

### Layer 5: Final Review — 跨任务集成

- **谁做**：最终的一个独立 reviewer（看到完整 diff）
- **检查什么**：task A 和 task B 之间的接口一致性、整体架构协调、全局模式问题
- **独特价值**：这是前四层都看不到的——没有一个 per-task reviewer 能看到跨 task 问题
- **绕过难度**：最高——最终防线

---

## 为什么多层比单层强

| 维度 | 单层"超严评审" | 五层纵深防御 |
|------|-------------|----------|
| 执行者 | 一个 | 多个不同 agent |
| 审查标准 | 一个视角 | 功能正确性 / 规格合规 / 代码质量 / 证据 / 集成——五个视角 |
| 盲区 | 一个 reviewer 的盲区 → 全漏 | 每个 reviewer 的盲区被下一个覆盖 |
| 绕过成本 | 绕过一次 | 需要绕过 5 次，每次不同的 agent |
| 上下文隔离 | 能受前面讨论影响 | 每个 reviewer 是全新上下文 |

## 前置防线

brainstorming 和 writing-plans 也在代码写出来之前有 self-review：

**Brainstorming self-review**（spec 写完后 4 项检查）：
1. Placeholder scan（找 TODO/TBD）
2. Internal consistency（前后矛盾）
3. Scope check（需要拆子项目吗）
4. Ambiguity check（任何需求有歧义吗）

**Writing-plans self-review**（plan 写完后 3 项检查）：
1. Spec coverage（每个 spec 需求有对应的 plan task）
2. Placeholder scan（不能有 TBD/TODO）
3. Type consistency（Task 3 叫 `clearLayers()`，Task 7 不能叫 `clearFullLayers()`）

---

## 配置分层

| 配置 | 层数 | 适用 |
|------|------|------|
| 最简 | TDD + verification（2 层） | 初级 |
| 中等 | TDD + spec review + verification（3 层） | 有信心 |
| 完整 | 全部 5 层 | 复杂项目、多 subagent |
