# 03 — 可借鉴模式：能拿出来用到别处的技术

## 这个目录研究什么

Superpowers 为了"让 agent 可靠地遵守规则"发展出了一套独特的工程技术。这些技术不只为 Superpowers 服务——它们可以迁移到任何需要 agent 行为控制的场景。

这个目录从 Superpowers 中**提取可复用的工程模式**。每一个模式都是：问题 → 解决方案 → 设计原理 → 怎么用到你的项目里。

---

## 为什么需要这个维度

Superpowers 的价值不只是"让你用 AI 写代码更高效"。它更大的价值是：**它证明了一套 agent 行为控制技术确实有效**。

- 借口 vs 真相表格：在对抗测试中反复迭代出来的，不是凭空设计的
- Bulletproofing：每一个堵上的漏洞背后都是一次 agent 绕过规则的测试记录
- 纵深防御：5 层防线不是设计文档里的架构图——是实际运行的检查链路

如果你要给自己的 CLAUDE.md 或技能文档设计类似的机制，这些模式提供了经过验证的参考实现。你不需要从零发明——你可以站在 Superpowers 的对抗测试结果上直接使用这些模式。

---

## 4 个核心可借鉴模式

| # | 模式 | 解决的问题 | 怎么迁移 |
|---|------|-----------|---------|
| 1 | Bulletproofing | Agent 在压力下找借口绕过规则 | 给你的指令添加：显式堵漏洞、借口反驳表、Red Flags、spirit-vs-letter 声明 |
| 2 | 借口反驳表设计 | Agent 有无限的自洽能力——总能给自己找到理由 | 用对抗测试捕获 agent 的实际借口 → 逐字反驳 → 反复迭代 |
| 3 | 对抗测试方法论 | 怎么知道你的指令确实有效？ | 设计组合压力场景（时间+沉没成本+权威+社交）→ 用 subagent 测试 baseline → 对比有/无指令的行为差异 |
| 4 | 纵深防御质量模型 | 单层防线总会被绕过 | 设计多层独立防线：TDD → spec review → code review → verification → 最终 review；每层由不同 agent 执行 |
