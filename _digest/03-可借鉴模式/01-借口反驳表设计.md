# 01 — 借口反驳表设计

## 这是什么

借口反驳表是 Superpowers 所有刚性 skill 的标配组件。两列：`| 借口 | 现实 |`。每条借口都是对抗性测试中 agent 的真实原话，每条反驳都是一个不可二次合理化的短回应。

这不是文档——这是行为代码。

---

## 四张现有表

### TDD（11 条）

| 借口 | 反驳 |
|------|------|
| "Too simple to test" | Simple code breaks. Test takes 30 seconds. |
| "I'll test after" | Tests-after checks implementation. Tests-first checks design. |
| "Tests after achieve same" | Different questions answered. Design vs implementation. |
| "Already manually tested" | Manual ≠ repeatable verification. |
| "Deleting X hours is wasteful" | Sunk cost fallacy. Hours coding wrong thing > hours deleted. |
| "Keep as reference, write tests first" | Reference = temptation to copy. Delete means delete. |
| "Need to explore first" | TDD IS exploration. Each test = one exploration. |
| "Test hard = design unclear" | Hard test = unclear spec. Fix spec, not skip test. |
| "TDD will slow me down" | Rework without tests is slower. |
| "Manual test faster" | Manual doesn't scale. Regression invisible. |
| "Existing code has no tests" | Normalization of deviance. Be the first. |

### Systematic Debugging（8 条）

| 借口 | 反驳 |
|------|------|
| "Quick fix for now, investigate later" | Quick fix without root cause = guessing. May not fix at all. |
| "Just try changing X and see if it works" | Shotgun debugging. You'll never know what fixed it. |
| "Add multiple changes, run tests" | Can't isolate which change worked. Unsustainable. |
| "Skip the test, I'll manually verify" | No regression protection. Bug WILL return. |
| "It's probably X, let me fix that" | "Probably" = guessing. Phase 1 is required. |
| "I don't fully understand but this might work" | Uncertainty = need MORE investigation, not less. |
| "One more fix attempt" (when 2+ failed) | STOP. Question the architecture. |
| "Each fix reveals new problem in different place" | Symptom of wrong architecture, not wrong fix. |

### Verification（8 条）

| 借口 | 反驳 |
|------|------|
| "Should work now" | RUN the verification. |
| "I'm confident" | Confidence ≠ evidence. |
| "Just this once" | No exceptions. |
| "Linter passed" | Linter ≠ compiler/tests. |
| "Agent said success" | Verify independently. |
| "I'm tired" | Exhaustion ≠ excuse. |
| "Partial check is enough" | Partial proves nothing. |
| "Different words so rule doesn't apply" | Spirit over letter. |

---

## 设计方法论

### 借口从哪来

不是预测的——是在 RED 阶段捕获的。设计一个 3+ 压力组合的场景，不给 agent 看 skill，看它选什么、说了什么理由。

然后把 agent 的原话逐字放入左列。不润色，不改写。用 agent 自己的措辞——这样 agent 在看到表时会有最高的自我识别率。

### 什么构成有效反驳

1. **一句话。** 不给 agent 继续辩论的空间。
2. **命令动词。** "RUN the verification.""STOP. Question the architecture." 不说"你应该考虑..."——说"做 X"。
3. **事实陈述，不是观点。** "Manual ≠ repeatable verification" 是事实。"Sunk cost fallacy" 是已命名的认知偏差。Agent 不能反驳事实。
4. **行动导向。** 每条反驳告诉 agent 接下来做什么，不只说"错了"。
5. **不共情。** 不说 "I understand why you'd think that..."——共情给了借口合法性。

### 饱和标准

继续 REFACTOR 循环直到 agent 在最大压力下不产生新借口。当 agent 说 "the skill was clear, I should follow it"——表完成了。

---

## 和 Red Flags 的关系

借口反驳表是"事后反驳"（你想到这个借口了 → 这是为什么它不对）。Red Flags 是"事前阻断"（你还没说出口 → STOP）。两者叠加：agent 在脑子里闪过一个借口 → Red Flag 触发 STOP → 如果继续合理化 → 借口反驳表里有对应的回应。
