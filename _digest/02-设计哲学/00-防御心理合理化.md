# 00 — 防御心理合理化

## 这个问题为什么重要

Agent 在压力下会找借口跳过规则。不是说 agent 坏——LLM 在时间压力、沉没成本、权威暗示的组合下，会自然地产生"这次就算了吧"的合理化。Superpowers 的核心设计挑战是：怎么让 agent 在多重压力下仍然遵守规则？

这不是写"要有纪律"能解决的。Superpowers 的回答是用对抗性测试发现 agent 的每一个借口，然后在 skill 里预先反驳它。

---

## 6 种核心防御机制

### 1. 显式否定

不只写规则——列举具体的 workaround，逐个禁止。

TDD skill 的 Iron Law 之后紧跟：

```
NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST.

If you wrote production code first:
1. Delete the production code.
2. Start over with a test.

Don't keep it as "reference."
Don't "adapt" it while writing tests.
Don't look at it.
Delete means delete.
```

这不是过度防御——每条禁令都对应一个在对抗性测试中观察到的 agent 行为。有一个 agent 在被要求删代码时说"keep as reference, write tests first"，看起来遵守了 Iron Law 实际上保留了违规代码。**下一次迭代就把这句话加进了禁令。**

### 2. "违反字的规则就是违反精神的规则"

```
Violating the letter of the rules is violating the spirit of the rules.
```

这句话出现在 TDD、systematic-debugging、verification-before-completion 三个 skill 中。它不是巧合——它关闭了一整类合理化。

这句话是在 testing-skills-with-subagents.md 记录的第 2 次 REFACTOR 迭代中加入的。迭代 1 的 TDD skill 只写了"先写测试"。Agent 用"test after achieves the same goals"绕过了。迭代 2 加了"Why Order Matters"章节。Agent 切换策略——"spirit not letter"（"我理解 TDD 的精神，先写代码再补测试没违背精神"）。迭代 3 加了这句话后，agent 不再能合理化。

**"违反字就是违反精神"不是哲学宣言，是一个具体的 bug fix。**

### 3. 借口反驳表

每个刚性 skill 都有一个 "Excuse | Reality" 表。每个借口和一个反驳配对。这不是通用原则文档——每个借口都是对抗性测试中 agent 的真实原话。

TDD skill 的 11 条借口+反驳：
- "Too simple to test" → "Simple code breaks. Easy to test."
- "Already manually tested" → "Manual ≠ repeatable verification."
- "Deleting X hours is wasteful" → "垃圾入，垃圾出。几小时浪费是沉没成本。"

Verification skill 的 8 条借口+反驳：
- "Should work now" → "RUN the verification."
- "I'm confident" → "Confidence ≠ evidence."
- "Different words so rule doesn't apply" → "Spirit over letter." （用不同措辞声称成功的 linguist evasion——被单独列出来禁止）

### 4. Red Flags 表

以 "STOP" 开头的自我检查表。Agent 产生某个想法时，看到对应的 Red Flag——产生认知摩擦。

TDD skill 的 Red Flags（13 条）：
- "Tests after will do" → STOP
- "This is too simple to test" → STOP
- "It's about spirit not ritual" → STOP
- ALL of these mean: Delete code. Start over with TDD.

Systematic-debugging 的 Red Flags（10 条）：
- "One more fix attempt" → STOP
- "Here are the main problems..." (listing fixes without investigation) → STOP
- ALL of these mean: STOP. Return to Phase 1.

### 5. 门函数（Gate Function）

按顺序执行的强制步骤序列。不能跳过——必须经过门才能产生输出。

Verification skill 的 5 步门：
```
1. IDENTIFY: What command proves this claim?
2. RUN: Execute FULL command.
3. READ: Full output, exit code.
4. VERIFY: Does output confirm the claim? (Boolean check)
5. ONLY THEN: Make the claim.
```

"Skip any step = lying, not verifying."

### 6. 铁律在全部大写

```
NO [action] WITHOUT [condition] FIRST
```

所有铁律用相同的结构语言。全部大写。绝对。无条件。没有例外。

不是 design choice——是基于 Meyke et al. (2025) 研究：权威性语言（"YOU MUST"、"never"、"no exceptions"）让 LLM 合规率从 33% 上升到 72%（p < .001）。"Bright-line rules reduce rationalization: 'YOU MUST' removes decision fatigue. Absolute language eliminates 'is this an exception?' questions."

## 说服心理学基础

`skills/writing-skills/persuasion-principles.md` 是防御系统的基础。基于 Cialdini (2021) 的说服原则 + Meyke et al. (2025) 在 28,000 次 LLM 对话中的验证。

| 原则 | 机制 | 用于哪些 Skill |
|------|------|-------------|
| **Authority** | "YOU MUST", "Never", "No exceptions" — 消除决策疲劳 | 每条铁律 |
| **Commitment** | 要求宣布 skill 使用、TodoWrite 跟踪、明确选择 | using-superpowers、writing-skills |
| **Scarcity** | "Before proceeding", "Immediately after X" — 阻止推迟 | TDD（先看它失败！）、verification（fresh evidence） |
| **Social Proof** | "Every time", "Always", "X without Y = failure" | 所有 skill 都使用绝对语言 |
| **Unity** | "your human partner" — 建立合作身份 | CLAUDE.md、receiving-code-review |
| **Liking** | 故意避免——在纪律 skill 中禁止感谢表达 | receiving-code-review 禁止"You're absolutely right!" |

## 从 6 次迭代看怎么建成一个防御系统

TDD skill 需要 6 次 RED-GREEN-REFACTOR 才 bulletproof（testing-skills-with-subagents.md 第 381 行）：

- **Iteration 1**: 写"先写测试"。Agent：跳过测试写代码。"tests after achieve the same goals."
- **Iteration 2**: 加"Why Order Matters"。Agent 换策略："spirit not letter."
- **Iteration 3**: 加"违反字就是违反精神"。Agent 终于遵守。
- **Iteration 4-6**: 关闭通过额外压力组合发现的新漏洞。

关键经验：**没有一个防御机制是一次写对的。每一个都是对 agent 真实借口的回应。** 这就是为什么 writing-skills 的铁律是 "NO SKILL WITHOUT A FAILING TEST FIRST"。

---

## 防御系统的三层架构

```
Layer 1: 1% 规则 (using-superpowers)
  → 消除"不需要检查 skill"这个最根本的借口
  → 如果不检查 skill，所有下游防御都失效

Layer 2: 铁律 (TDD, debugging, verification, writing-skills)
  → 全部大写、绝对语言、无条件
  → 消除"这是例外吗"的认知搜索

Layer 3: 门函数 (verification, brainstorming's HARD-GATE, SDD quality gates)
  → 按顺序执行的强制步骤
  → 消除跳过或重排的合理化
```
